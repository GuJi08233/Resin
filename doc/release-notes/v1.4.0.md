# Resin v1.4.0

## Managed WARP Exits

- WARP exits are managed in a dedicated subscription instead of per-node configuration. Enable it once and Resin registers Cloudflare WARP devices through UDP-capable parent nodes, with a configurable exit limit (default 300) that scales up and down automatically in the background.
- Exits are created with bounded parallelism and IPv6-first family balancing. Parents are warmed up independently, duplicate egress IPs defer retries, and verified parent/family latency metadata is persisted so a restart recovers without re-probing everything.
- Parents that cannot carry UDP are detected with a DNS query before device registration and skipped; explicit refusals (for example SOCKS5 `UDP ASSOCIATE` code 7) pause all families at once. Repeated parent failures pause that parent with a doubling backoff (30m up to 6h) and recover on the next success.
- Unused devices from failed attempts are reused instead of registering new ones, and Cloudflare registration pacing plus `Retry-After` are respected without penalizing the parent.
- WARP nodes appear in the node pool alongside subscription nodes. Platforms can exclude them independently, and the original subscription nodes remain available.
- Subscription management shows IPv4/IPv6 exit counts, maintenance progress per phase, and tunnel diagnostics (parent identity, endpoint, handshake and packet counters).

## Native Mieru Support

- Resin can now build Mieru outbounds natively (TCP and UDP), alongside the existing sing-box protocols.

## Egress IP Profiles (IPPure)

- Optionally probe `https://my.ippure.com/v1/info` through each node's own egress to record the exit IP's location, ASN, organization, fraud score, native/broadcast status, and residential/hosting status. Disabled by default: turn on `ipinfo_probe_enabled` in the runtime config.
- Probes reuse the existing worker pool, dual-priority queue, and per-node deduplication. Failures only record the attempt timestamp and never touch the circuit breaker.
- `POST /api/v1/nodes/{node_hash}/actions/probe-ipinfo` triggers a one-off probe and returns the profile. Profiles persist in `cache.db` and are restored on startup.
- The nodes table, node details, and system config pages show IP type, risk score, ASN, and location.

## Platform and Node Pool Filtering

- Platforms gain `ipinfo_filters`: a risk-score range, IP type (`residential`/`hosting`), native type (`native`/`broadcast`), and ASN allow/deny lists. Once any condition is set, nodes without a profile are not routed by that platform.
- Node listing accepts the same filters plus `has_ipinfo`, and supports `sort_by=fraud_score`. Nodes without a profile always sort last.
- Region resolution now falls back through explicit probe region, GeoIP, and finally the profile's country code, so region filters keep working without a GeoIP database.

## Upgrade Notes

> [!IMPORTANT]
> `state.db` gains an `ipinfo_filters_json` column on the `platforms` table and `cache.db` moves to schema version 3 with `ipinfo_json` / `last_ipinfo_probe_attempt_ns` on `nodes_dynamic`. Both migrations are additive and run automatically at startup; existing platforms and nodes are preserved.

- Back up `<RESIN_STATE_DIR>/state.db` and `<RESIN_CACHE_DIR>/cache.db` before upgrading.
- WARP configuration migrated from per-node settings to the dedicated subscription. Previously created WARP exits are re-created by the background maintenance loop; no manual action is required.
- IP profile probing is off by default. Manual probes still work while periodic probing is disabled.
- Multi-platform GHCR images (`linux/amd64`, `linux/arm64`) continue to publish on every master push and on version tags.
