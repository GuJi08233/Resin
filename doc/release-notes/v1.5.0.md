# Resin v1.5.0

## Latency Filtering & Sorting

- Platforms gain `latency_filters` (`min_ms` / `max_ms`, inclusive bounds in milliseconds) matched against each node's reference latency (average EWMA across configured `latency_authorities`). Once any bound is set, nodes without a reference latency sample are not routed by that platform.
- Authority latency updates automatically re-evaluate platforms with an active `latency_filters` rule, without triggering rebuilds on platforms that do not filter by latency. Updating `latency_authorities` in system config also rebuilds latency-filtered platforms immediately.
- `GET /api/v1/nodes` supports `min_latency_ms`, `max_latency_ms`, `has_latency`, and `sort_by=latency`. Nodes without a reference latency always sort last regardless of direction.
- `POST /api/v1/platforms/preview-filter` supports `latency_filters` in `platform_spec` as well as via `platform_id`.

## Continent (Macro-Region) Filtering

- Platforms gain `continent_filters` supporting all seven standard two-letter continent codes (`as` Asia, `eu` Europe, `na` North America, `sa` South America, `oc` Oceania, `af` Africa, `an` Antarctica) with optional `!` negation. Continent filters combine naturally with `region_filters` (for example selecting Europe `eu` while excluding `!ru`), and exclude nodes whose country cannot be resolved.
- `GET /api/v1/nodes` supports `continent` (single, comma-separated, repeated, and `!` negation).
- `POST /api/v1/platforms/preview-filter` supports `continent_filters`.

## WebUI Enhancements

- Both the platform creation modal and platform configuration page include a three-state continent pill selector (unset / include / exclude) and reference latency min/max inputs, with continent count and latency range displayed on platform cards and detail headers.
- The Node Pool page adds a continent filter dropdown, a reference latency (ms) min/max range filter, and a clickable reference latency sort header.

## Upgrade Notes

> [!IMPORTANT]
> `state.db` moves to schema version 13, adding `continent_filters_json` (`DEFAULT '[]'`) and `latency_filters_json` (`DEFAULT '{}'`) columns to the `platforms` table. The migration is additive and runs automatically at startup; existing platforms are preserved with no continent or latency restrictions.

- Back up `<RESIN_STATE_DIR>/state.db` and `<RESIN_CACHE_DIR>/cache.db` before upgrading.
- Multi-platform GHCR images (`linux/amd64`, `linux/arm64`) and release binaries continue to publish automatically on version tags.
