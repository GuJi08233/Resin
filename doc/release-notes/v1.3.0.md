# Resin v1.3.0

## Platform-Scoped Status Code Rules

- Each Platform can now define its own HTTP status code rules: `COOLDOWN` an egress IP for a configurable duration, or `BLACKLIST` it permanently.
- Rules accept exact codes or inclusive ranges (for example `403`, `429`, or `500-599`) and are edited from the Platform create dialog and config tab.
- Actions are scoped to a single Platform and keyed by egress IP: every node sharing that IP stops being routable for that Platform, while other Platforms and global node health are unaffected.
- Cooldowns recover automatically when they expire. Blacklists stay until an operator unblocks the IP from the Platform ops tab (`GET /api/v1/platforms/{id}/exclusions`, `POST /api/v1/platforms/{id}/actions/unblock-egress-ip`).
- Cooldowns and blacklists are persisted in `state.db` and survive restarts.
- HTTP forward and reverse proxy traffic can observe status codes; CONNECT and SOCKS5 tunnels cannot.

## Upgrade Notes

> [!IMPORTANT]
> Persisted legacy Platform regex filters are automatically migrated to composable tag-filter rules during startup. This database migration is irreversible because earlier releases cannot represent OR or exclusion rules.

- The v1.3.0 schema additions are additive: existing Platforms are preserved and receive an empty `status_code_rules` list. No manual database action is required.
- Back up `<RESIN_STATE_DIR>/state.db` before upgrading.
- To downgrade to an earlier release, stop Resin and restore the pre-upgrade backup. Do not attempt to roll back the migrated database.
