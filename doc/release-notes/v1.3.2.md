# Resin v1.3.2

## Fixes

- Apply status-code cooldowns and blacklists before returning upstream response headers, so immediate retries cannot reuse the excluded egress IP while the platform view is rebuilding.
- Check live exclusions for random routing, sticky leases, and same-IP node rotation. Other platforms remain unaffected.
- Allow an expired cooldown to trigger again even before the background expiry sweep removes the old record.

## Upgrade Notes

- No database changes. Drop-in upgrade from v1.3.1.
- Status-code rules apply to plain HTTP forward proxying and HTTP/HTTPS reverse proxying. CONNECT and SOCKS5 tunnels do not provide status-code feedback; HTTPS clients needing these rules should use reverse proxying.
